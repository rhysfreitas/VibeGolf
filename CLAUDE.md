# VibeGolf: notes for coding agents

Golf simulator for the Garmin Approach R10. Static site served from the repo root by GitHub Pages. There is **no build step and no bundler**.

## Ground rules
- Three.js is **r147 UMD**, vendored in `vendor/three-r147/` and used as the global `THREE`, including `THREE.Sky`, `THREE.Line2`, `THREE.LineMaterial` and `THREE.LineGeometry`. Each page loads those classic scripts first, then its ES module. Moving to a newer Three.js means switching to an importmap plus `three/addons/...` and updating every `THREE.Xxx` add-on reference.
- `src/physics.js` must stay pure: no DOM, no Three.js, SI units inside, mph/deg/rpm at the boundary. Input follows GSPro Open Connect `BallData` naming (`Speed`, `VLA`, `HLA`, `TotalSpin`, `SpinAxis`).
- Coordinates: x = right, y = up, −z = downrange. On the course, each hole has its own frame with the tee near the origin.
- `groundAt(x, z)` returns `null` over open air. The physics treats that as no ground: the ball can fall into the void, hit cliff walls or roll off edges.
- Run `npm test` after touching physics. The calibration test keeps carries within 5% of TrackMan tour averages. If you change coefficients on purpose, refit them rather than loosening the test.
- Live shots come only through `src/launch-monitor.js` (`launchMonitor` emits `shot` events). Don't add another path.
- Simulated shots come only through the shared tool in `src/sim-tool.js` (one small button, a fly-out with club, Normal / Punch / Stinger, a draggable shape line, a swing-length bar (% of full, Full by default), Ideal and Hit). Every mode uses it: the kit for mini games, and the range and course directly. `src/minigames/aim.js` has the matching solver (`solveCustom`, `makeToolShot`, `amateurMiss`, `TRAJ_MUL`). Keep it minimal on screen so the view reads like play with an R10.
- The phantom aim line (`src/aim-line.js`) shows the next simulated shot as a dashed arc with a ‹ ○ › landing marker. A sideways drag on the 3D view swings it (`attachAimDrag`, which starts after 10 px so taps still reach the page), and the shot flies down it. The crosshair beside the tool's pill is **Auto-aim** (off by default, remembered in `vibegolf.autoAim`): on, the game's solver plays the shot (club, swing length and direction to its target) and the bar reads Auto; off, the shot is your club at your swing length down your line. Grabbing the line or the bar turns auto-aim off and keeps the shot it was playing (`seedPct`). A map tap, or picking a target, sets the club and swing length that reach it. Turning a shot is just adding to HLA (`turnBall`, `aimTurn` in `aim.js`), which turns the whole flight about the ball on flat ground.
- Page styles live in `styles/<page>.css` with tokens on `:root`. Shared bits (launch-monitor popover, status dot, menu link) are in `styles/shared.css`.

## Layout
Both modes are **landscape-first** (phone held sideways). The camera "stands over the ball": `src/stance.js` solves a position a few metres behind the ball at eye height and a pitch that puts the ball near the bottom centre at any aspect ratio. The view is **fixed**, a window into the world: it never tips up or down to follow the ball or to frame targets (a high wedge can leave the top for a moment; the tracer still draws it). Deliberate cuts for the payoff stay: Golf Bowling's glide to the pins and the course's landing view. Controls sit in a bottom-left cluster (`#hitbar`), the readout is bottom right, and settings live in fly-out `.sheet` panels. There is one camera per mode by design. On the course, the corner map's ⤢ button is the only view switch (whole hole); tapping the map itself aims at that spot, and dragging the dashed aim line swings the shot without turning the view (`state.yaw` is the shot, `state.camYaw` the way you face). Check changes at 844×390 and 667×375 (phone landscape) and at desktop size. Portrait gets a dismissible "turn sideways" prompt on touch devices.

## Gotcha: Line2 tracers
Three r147 caches an instanced geometry's draw count (`_maxInstanceCount`) the first time it renders. Any `Line2` whose point count changes (growing tracers, preview arcs) must reset `geometry._maxInstanceCount = undefined` after `setPositions`, or it stays frozen at its first length. The helpers `setLinePositions` (range) and `setLine` (course) already do this. Line widths are in device pixels, so scale them by `renderer.getPixelRatio()`.

## Visual checks
Serve the folder (`npm start`) and drive it headlessly with Playwright. Set `window.__lowq = true` in an init script so it renders at software-GL speed, call `__advance(seconds)` to step the simulation deterministically (`__advance(seconds, n)` also renders every nth step, which is how real play behaves; use it for anything that changes frame to frame), and on the course set `window.__pose = { pos:[x,y,z], look:[x,y,z], fov }` for a fixed camera. `__state` exposes course game state and `__startHole(i)` jumps holes. For course reviews, `tools/review/` has ready-made tools (no server needed): a rules check per hole, simulated drives, plans with profiles, clean tee/landing/green renders, and an auto-aim play-through of every hole (see its README).

## Courses
The home menu has four cards: Practice Ground (`practice.html`), Play Golf (`courses.html`, one tile per course; add a tile for each new course), Mini games (`games.html`) and Online (`online.html`, a placeholder for the friends lobby). `course.html` plays any course module: `?c=aerie` (default; `?c=aerie2` is an old alias), `?c=redmesa`, `?c=hollowmere` or `?c=reclaim`. A module exports `COURSE` (`id`, `name`, `theme` 'sky', 'mesa', 'cave' or 'city', `altFt`, `signature` conditions, four `teeSets` with `minDrive`, optional `voidText`) and `HOLES`. Keep the hole format stable, because the planned course builder will read and write it:
- Laying out a new course (rules of thumb, agreed with the owner): plan first (a yardage-book PDF on white pages: plan, side view, how it plays), then an in-game blockout with sketched views from the tee, the landing area and the green. Vary the hole shapes (doglegs both ways, a cape, an S-bend, straight holes only now and then). **Use elevation on every hole**: several holes 8–15 m up or down and two or three big ones (25–35 m: a drive off a ledge, a climb to the last green), never a run of flat holes. Within holes, always consider tilted fairways (a cant toward trouble), terraces or steps (where the ball stops sets the lie), crests and blind shots (with a marker on the line), and raised greens (false fronts) and sunken ones (punchbowls). Add variety, fun and challenge without making it overly hard: fairways 45–65 m wide where drives land, short grass round greens, a safe way round every forced carry, and only a few real bold-or-safe choices. Plays-like yardage belongs in the game, not on the card. Keep anything overhead (a roof, an overhang) at least 45 m over every tee so normal shots clear it. More, from Hollowmere (the full notes are `docs/COURSE-DESIGN.md`): build elevation from the floor and wide landforms (a `step` ramp from wall to wall), not raised slabs whose edges stand as cliffs; the ground round fairways and greens can roll, but no plateau-like rises along their edges unless one is a thought-out feature of that hole (fix the shape rather than leave an accidental shelf), and nothing kicks toward trouble on a hole that's already hard; a miss must cost (walls that drop a wild ball into rubble, stalagmite stands, groves, water) while landing areas stay wide; one continuous pool is a river channel at one level; check a dogleg's direction from the geometry; give every hole fairway `targets` (auto-aim plays the pin straight through a dogleg's corner otherwise) and play each hole headless tee to holed; nothing floats; and review each round with a book of in-game views (tee, landing, short of the green) plus the plan and its elevation profile, white pages, room for notes.
- The Reclaim (`src/course/reclaim.js`, theme 'city', a blockout, `?c=reclaim`) is a ruined, overgrown city, generated from the plan book's data in `tools/reclaim/` (edit `holes.mjs`/`scene.mjs`, run `emit.mjs`; don't hand-edit the module; the plan book tools are in its README: plans, profiles and projected SVG sketch views, minutes a round). Its holes carry `field`: the ground sampled every 2 m (heights and surface codes, base64; `terrain.js` `prepField`, NaN = open air for the rift and the sinkhole), with the green, bunkers and tee pads as shaped features over it; `rocks` of type 'box' (buildings, `soak` 0.45 on facades so a wild ball drops at the foot, as cave walls do; cars; columns) and 'wedge' (the El's deck, the fallen towers and their chunks); `plants` (trees that play); `frame` (where the hole sits in the city). `COURSE.city` is the city once, in world space (buildings with broken tops `b`, open lobbies `open`, `lean`, the clock `tower`, ivy `v`; the El; spans; cars and cabs; poles, cranes, the bridge; water and the river); `src/course/city-world.js` (global `THREE`) draws what's near each hole into its frame, merged into a few meshes. main.js runs it down the Red Mesa path (`CITY` is part of `MESA`; `DESERT` is the red-rock look), with the playfield's `steepFine` and `snapEdges`, the shader's `CITY` define (cracked asphalt with grass up the cracks, concrete banks), a misty grey sky under overcast, the lie 'Street' for native ground, and a corner map painted from the surfaces (`paint` in minimap.js). `tests/reclaim.test.mjs` checks yardages, tees, pins, nothing overhead, targets on fairway, drives clear, the Atrium's lobby, the fallen tower's ridge, the sinkhole, the rift, the river and the soaking facades.
- Islands are superellipses (`rx`, `rz`, `rot`, `top`, `depth`, `kind`, optional `p` for squareness) with optional `green`, `pin`, `bunkers`, `falls` and `trees`. Kinds: 'tee', 'fairway', 'rough', 'green' (the Aerie's), 'mesa' (a playable top: rough unless painted) and 'rock' (cliffs and walls). `slope: { from:[x,z,y], to:[x,z,y] }` makes a ramp.
- Per hole: `tees` (`{ setId: [x, z] }`), `yards` (`{ setId: n }`), `pin`, `heading` (compass bearing, for the sun and wind), `targets` (course-management picks), `drops` (penalty drops). Red Mesa adds `line` (the playing line tees are measured on), `floor` (`{ y, relief, solid, washes, gorges }`: the canyon floor; `solid: false` is scenery only, open air for the ball), `fairways` and `sand` painted on any ground, `rocks` (arches, hoodoos and boulders the ball hits; a hoodoo with `taper: true` and `cap: 0` is a stalagmite; an arch takes `crown` (span thickness as a share of `t`) and `flare`/`fh` (legs widening into buttresses); `pe` squares a boulder into a block, and a boulder with `y` set sits up in the air, as the cap of a table rock), `rockfalls` (piles of fallen rock heaped toward a wall or a boulder, native ground, with solid boulders scattered over them; a pile's foot follows the ground along its length, so one along a ramp climbs with it), `groves` (stands of trees placed on purpose, in play), `rivers` (`{ pts, w, depth }`: a smoothed channel filled to one level, 'water' with a stroke and a drop; it never notches a cliff it runs past), `corridor` (0 = no rough down the middle: miss the targets and it's native), `teePads` (`{ setId: { w, l, h, rot } }` for a bigger, higher or turned pad; a pad stops at a ledge's lip, so a tee at the lip looks straight down) and `props` (scenery by type). No tee sits on a fairway (tested): forward tees go on their own pads beside it.
- Shaped features (`src/course/features.js`, pure): `green` (a complex: `style` 'tilt'|'tiered'|'crowned'|'plateau'|'punchbowl'|'redan'|'biarritz', `tilt`/`side` %, `raise`, `apron`, `falseFront`, `tiers`, `swale`, `runoff`, and `pins`, one picked per round), `bunkers` (bowls with lips: 'flashed'|'pot'|'grass'|'waste', face rises `toward` the green), `landforms` ('ridge'|'swale'|'mound'|'bowl'|'tilt'|'step' for speed slots), `water` (ponds with a level) and tee pads (every `tees` entry is a raised, mown pad facing down the line). Each has a local frame: `rot` is the yaw of its back (0 = down the hole), or `from`/`toward` a point. Ground = base (islands, floor) + landforms, blended to ponds, rivers, greens and tee pads, rockfalls heaped on, then bunkers carved in. A floor wash runs on through a green's surrounds as waste. Pins stay at 3% or less (tested).
- Surfaces: 'tee', 'fairway', 'fringe' (collar and short-grass runoffs; plays as fairway, putts when close), 'firstcut', 'rough', 'desert' (native ground and the canyon floor; on Red Mesa the corridor along `line` is rough, outside it and across the carry from the back tee is native), 'sand', 'waste', 'water' (a stroke and a drop beside where it went in), 'green', 'void'. A fairway mown up to a green, bunker or tee keeps its fairway (their outer rough gives way). Lies cost distance in that order; native sometimes gives a bad lie. The slope under the ball changes every shot, simulated and live (uphill launches higher, ball above the feet pulls left). Putting odds read the green: break, downhill speed and tiers lower them.
- Trees play, on both courses: `src/course/trees.js` (pure) turns the renderer's tree list into bodies (a trunk under a canopy ellipsoid, sized like the meshes). Physics takes `treeAt(x, y, z)` and `rng`: a trunk bounces the ball, and inside a canopy each metre travelled has a chance of a branch that knocks it down or kicks it sideways. Only the real shot passes trees (`shotFrame(..., live = true)`); previews and the aim line fly clear.
- The Aerie (`src/course/aerie.js`) is a sky course with `COURSE.shaped`: drawn like Red Mesa's playfield (the surface paint texture, shader define `PAINT`; `MW.buildPlayfield` over the island tops, each top ring following the shaped ground, sunk 1.5 m inside the rim; ponds from `MW.buildWater`; props through `MW.buildProps(..., { glyphs: false })`), with islands, painted fairways, green complexes, bunkers and landforms but no floor (`corridor: 9999`, `native: [0, 0]`). Its `hole.scenery` is what floats over the hole: `hanging` islands (a top, the underside tapering down to `bottom`), a `drift`ing island (moves a long way along `path` between shots, sways a little in real time: `moveDrifts` in `sky-props.js`, `driftTo` in `terrain.js`), `wedge`s of rock (blocky, faceted prisms from `from` to `to`, each `[x, z, y]`, tapering by `w`/`h` [root, tip], optional `drop` buttress down the island's side; `wedgeParts` gives the pieces), `falls` (a sheet off the nearest rim, as wide as `pts`; `makeFall(I, th, width)`), the `balloon` (scenery only). `terrain.js` turns the floating islands and wedges into solid rock (`T.floats`, rock types 'float' and 'wedge') and the falls into `T.curtains`; `T.curtainAt(x, y, z)` reads as a dense canopy in the live shot (`treeAt`), so a ball through a waterfall is knocked down. `src/course/sky-props.js` (global `THREE`) draws all of it from those same shapes, plus `hole.distant`: the other holes' `LANDMARKS`, placed where the course map puts them (`rot` in degrees), scenery only. (`overhang` slabs and `crag`s still draw, but nothing uses them.)
- The clouds are a red penalty area (Rule 17): `src/course/relief.js` `cloudDrop` drops the ball on firm grass within about two club lengths of where it last left an island, no nearer the hole, never in sand, water or on a green; with nowhere to drop, it's stroke and distance.
- `src/course/terrain.js` is pure and shared by the renderer, the physics and the tests: `createTerrain(hole)` gives `groundAt` (highest top, else the floor, else `null`), `surfaceAt` ('desert' is the canyon floor), `solidAt(x, y, z)` (outward normal inside rock) and `voidY`. Physics takes `solidAt` and `wind` (`{x, z}` m/s in the shot frame) as options; walls that rise above the ball knock it back, in flight and rolling.
- `src/course/conditions.js` is pure: time of day, wind (rolled once per round, shifted a little per hole), weather, temperature, compass-to-hole maths and the tee suggestion (median of recent drives from `src/drives.js`, localStorage `vibegolf.drives.v1`). The round setup screen sets them; each course opens on its signature conditions. The chosen tee set is remembered per course (`vibegolf.course.<id>.tee`).
- Red Mesa's scenery is `src/course/mesa-world.js` (global `THREE`): the floor mesh, the playfield (one grid over the hole's box sampled from the shaped ground, under a metre per cell around features, with skirts between tiles; island tops inside the box are left to it; where the ground drops a cliff, `levels` draws each level (an island's top, the floor) on its own up to that island's outline, and `buildMesa` sets the wall's top edge there to the shaped ground, so rims meet their walls without the old saw-teeth), a per-hole surface paint texture the island shader reads (R short grass, G green, B sand, A grass length: first cut, rough, native), ponds, cliff walls down to the floor, arches, hoodoos and boulders built from the same shapes the physics hits, plants (scattered trees stay 20 m off every tee-to-pin line and clear of fairways and green surrounds, `inPlay`; groves are where the hole wants them), props (windmill, mine, trestle and train, waterfall (finds the cliff's lip itself), fossil, balanced rock, clubhouse, observatory, window arch, petroglyph tee markers, kestrels, swallows). Prop `rot` is the way it faces: local +z → (sin rot, 0, cos rot).
- Hollowmere (`src/course/hollowmere.js`, theme 'cave') is generated from the plan book's world-frame hole data in `tools/hollowmere/` (edit `holes.mjs`, then run `sample.mjs` and `emit.mjs`; don't hand-edit the module). Nine holes through old mine caverns; four of them share the Hollow, a great cavern with a chasm (the Deep: floor `gorges`, open air) and a waterfall. A cave course is built like Red Mesa (floor, playfield, rocks, water; the shader's `CAVE` define gives limestone and cave mud) plus `hole.cave` (`src/course/cave.js`, pure): `halls` (capsules `{a, b, w}` or ellipses `{e, rx, rz, rot, p}`, each with `roof` and `foot` heights, optional `wall`: the metres it rises over, for a dome like the vault over the Deep), `sky` openings `{x, z, r, upper? { h, r, sky }, cenote? { terraces, step, ledge } | { vines: true } }` (upper: a second cavern above the opening, drawn only, with its own skylight; falls near it pour off its lip; cenote with terraces: open to the sky from its floor, walls stepping back in planted terraces, falls with `cascade: k` tumble down them; cenote with vines: a ragged hole in a domed roof, vines hung from its lip, moss and ferns round it, falls with `through: true` pour in through it), `wall`, solid `stalactites` `{x, z, y (tip), r}` and `marks` (lanterns, crystals, glowworms (`dense: true` for the grotto's ceiling), falls, adit, rails, trestle, ferns, clubhouse, `hang` stalactite curtains `[x, z, len, r]` (scenery only), `geode` `{x, z, r, from, back}` (the green in the lower half of a cracked geode: crystals inside its rim (the rim itself is mound landforms), an agate band on the crest, the upper half on end behind it at `back`), `crystalcave` `{x, z, r}`, `gours` (rimstone pools over real ponds), `stack` (fallen rock stacked up the steep bank in front of a green)). `hole.cave.cart` `{ route }` is an ore cart on rails: terrain's `makeCart` keeps where it stands (`T.cart.s`), it rolls on between shots (`T.cart.next()` in `nextLie`) and is a solid box for the ball. The rock is irregular, the same for the ball and the mesh: walls wander in and out (`wallDepth`), the roof rises in vaults and hangs in ribs. `ceilingAt(x, z)` is the roof curving down into the walls (null under the sky); terrain's `solidAt` includes it, so the roof, walls and stalactites are rock for the ball. The normal carries `soak` (walls 0.45, stalactites 0.2): the chance a hit kills the ball so it drops at the face, and the foot of every wall (`wallDepth` under 9 m) is a rubble lie ('desert'). Big misses are meant to cost: stalagmite stands (hoodoos with `taper`), mushroom groves and walls that don't throw the ball back. A hoodoo with `column: true` runs floor to roof, flared at both ends (a flowstone column in front of a back tee). In `holes.mjs`, `streams` are split into level river pools where the ground drops. A hole's landforms shape its own floor, never another hole's ground (scenery islands keep their height: `sceneryAt` in terrain/features), and holes climb on floor ramps (a wide `step` landform) rather than slabs whose edges stand as cliffs. Cave playfield tiles go fine wherever the ground is steep (`steepFine`). Islands with `scenery: true` are other holes' ground in the same cavern. `src/course/cave-world.js` (global `THREE`) draws the roof and walls from `ceilingAt` (pushed in and out where the sheet stands up as wall), rubble, fallen blocks heaped two high and flowstone along the wall feet, sky shafts as sunlit funnels with sunbeams and spotlights (the upper cavern, the cenote's terraces and plants), clustered stalactites, the marks, and giant mushrooms (`groves` of `type: 'mushroom'`, which play as trees: trees.js). No sky, a dim fill and dark fog: the play is lit by lanterns, the sun through the roof, a light on the green and one down the fairway. **Only the green's and the fairway's spotlights are real lights** (the same two on every hole, so shaders compile once per round): every other cave light goes in `ctx.baked`, and `bakeLights()` (end of `buildHole`) bakes it into the meshes, per vertex (per instance for instanced meshes), with Three's own falloff and cone, plus each vertex's three strongest lights for the shine. New cave lights go in `ctx.baked`, never `group.add`; anything that moves sets `userData.noBake` (the ore cart). Where the roof meets a sky opening, its points are pulled onto a ring just inside the shaft (`rimEdge`), and each shaft's bottom ring is laid on that same edge (`sealRing`), so nothing shows through round an opening. Chasms (floor `gorges`) get a rock wall down from their outline (`buildGorgeWalls`; none where one chasm runs into another), the playfield ends on that outline (`buildPlayfield` `snapEdges`) and so does the far floor, which is fine (4–5 m cells) round the chasms (`buildFloor` `gorgeEdge`); a coarse cell laid across a chasm used to slope fairway paint down into it or leave a lid over it. Fifteen-odd real lights made every pixel loop over all of them and the play crawl on phones. `cave.js` `wallDepth`/`ceilingAt` skip halls that can't change the answer and work out their noise once per point (exact; every hole carries all the halls): keep any edit to them exact. Floors under every hole catch balls in the crevices (lie 'Cave floor'). Every hole lists `targets` on fairway (tested): on a dogleg the pin's straight line runs through rock, and auto-aim needs a corner to play to. Auto-aim (`nextLie` in main.js) takes the pin when it's in reach and `flightClear` (no rock or rising ground under a rough arc), else the first clear, reachable target in order, skipping one under 60% of reach when a further one is in reach.
- `tests/features.test.mjs` checks each feature on a synthetic hole (a false front sends a short approach back, a ball stays in a bunker, a speed slot adds yards, ponds, tee pads, rough cuts, a grove knocking shots down, a trunk, a boulder, a rockfall). `tests/aerie.test.mjs` checks the Aerie: card yardages, tees on their pads, pins at 3% or less, ground all round every green, the Veil's falls knocking a pulled drive down, the Cape's cove carry, the drifting island blocking a punch only when it's on the line, rock that's solid but out of the way of normal shots, the 9th reachable in two, and the cloud drop. `tests/red-mesa.test.mjs` checks tee yardages on the line, tee boxes off the fairways, every pin on its green at 3% or less, Rimrock's boulder and ledge, The Chute's shelf, grove, wash and green, Kestrel's drops, Needle's Eye's long diagonal arch (normal drives pass under it, a high one clips the span, shots at either foot hit it), hoodoos, the floor and the gorge. `tests/hollowmere.test.mjs` checks cave.js (the roof, walls, openings, stalactites), tees and pins (on ground, pins at 3% or less, the roof 45 m or more over every tee), that normal drives hit nothing in the air, walls that soak, the Cenote drivable through its eyelet (a low drive stopped by the fin), the Falls' stalactites and the Deep, and the Adit's cart (solid, and it moves on). Run `node` on a map script against `createTerrain` to see a hole from above before rendering it.

## Coaching range
- The Practice Ground (`src/world/practice-ground.js`) is the range page's world, a night tour campus (Woodson Range is retired; the clubs table is `src/world/clubs.js`): blue-hour sky, a city skyline, floodlights as light pools in the ground shader, glowing target greens, lit boards, a big screen (`showShot`), empty bays, the Swing Lab (canted roof 3.6 m to 7.5 m so lofted shots clear the opening, a horseshoe capture rig open toward the target), the coach gate (`setGate`) and the short-game area behind a lit hedge. One campus, three stations (`STATIONS`: tee, lab, short); `setStation()` slides the world so the station's ball is at the origin, so the range code is unchanged. Coaching uses the lab. `world.tick(clock)` runs its lights each frame.
- The home card opens `practice.html` (Range, Coaching, Short game and Bag Mapping coming), which links `range.html?mode=range|coach`. `range.html` with no mode opens the same choice as an in-page menu. Coaching is mapped in `docs/COACHING.md`; the full spec is the Coaching Range spec doc.
- The rules are pure and tested: `src/coach/coach-logic.js` (impact metrics, `RULES`, the 4-shot window, `pick`, `createCoach()`), `windows.js` (per-club windows scaled from the tour averages through the flight model), `conditions.js` (the catalogue), `faults.js` (Swing fault presets for simulated shots) and `lessons.js` (mannequin lesson data). No DOM or Three.js in any of them. Run `npm test` after touching them.
- Decided numbers: read after 4 shots with one club (3 of 4 agree, none the opposite miss), progress after 8 on the cue, quiet for 10 shots after a dismiss unless it gets worse, coaching per club, history in `localStorage` `vibegolf.coach.v1`.
- `src/coach/mannequin.js` is the 3D golfer (global `THREE`): ten P-position keys blended in the chest's frame, the club as a quaternion, one renderer moved between slots with `mount(el)`. Lessons only change the base swing where the fault lives. Numbers on screen are read off the scene.
- Learn a skill (`src/coach/skills.js`, pure; tested in `tests/skills.test.mjs`): Coaching opens on a choice, Watch my swing or Learn a skill. Nine skills, each with options, a club rule, two or three keys (mannequin lessons in `lessons.js`, `skill-*`: you = your normal swing or the usual miss, goal = the skill's swing), goal windows and ordered blockers. Hit in fours; 3 of 4 in the goal, then a test of 5 of 8, then open-ended. Skills measured against your own shot take four normal swings first. Only a shank or a run of fat shots interrupts. Learned skills: `localStorage` `vibegolf.skills.v1`. `?mode=coach&skill=shape.draw` opens a lesson.
- `src/range/coach-ui.js` shows what the rules decide; the range calls `coachUI.shot(shot, clubId)` when a shot finishes. The shot tool's Swing fault (`faults` option on `createSimTool`) only exists on the range.
- Headless: `?mode=coach` opens on the choice; click `[data-m=watch]` (or `[data-m=skill]`, then a `.co-skill`, then `.co-go`), set `.st-fault select`, press `h`, `__advance(16)`, wait for `.st` to lose `busy`; `window.__coachUI` is the test hook.

## Mini games
The design for all eight mini games, and the shared gamification kit they must use, is in `docs/MINIGAMES.md`. Build to that spec and keep every game at the same level. Don't add slot or card reveals, unlocks, boss stages, or fast-moving targets.

How a mini game is put together (Shape It is the reference):
- `games.html` is the menu. Each game is its own page (`shape-it.html`) loading `styles/minigame.css` and one module.
- `src/minigames/kit.js` is the shared kit: start screen (difficulty, players, three run challenges, best), turns and scoreboard, `award()` with the ×4 streak, `splash()`, `soClose()`, `stat()` → challenge stars, `endShot()` / `next()`, end screen and bests (localStorage `vibegolf.best.<game>.<difficulty>`), the bottom-left prompt + the simulated-shot tool, the bottom-right result card, and synthesised sounds (`kit.sfx`). Modes: `'shots'` (N shots each), `'run'` (survival runs) and `'manual'` (the game picks the next player with `kit.turnTo(i)` and ends with `kit.finishGame()`, as Golf HORSE does). Optional: `cpu` + `minPlayers` add a computer player when you're alone (phase `'cpu'`, the game swings for it, no bests), `options` adds start-screen choices passed in the `start` event, `rankBy` orders the end screen, `board: false` hides the side scoreboard, `aimLine({ world, view, sim, ideal, manual, seedPct })` draws and aims the phantom line (`ideal(s)` is the game's auto-aim ball for the tool's settings, aimed at its target; `manual(s)`/`seedPct(s)` only for games that hit partial swings their own way, like Golf Bowling's knockdowns), `hit`/`ideal` events carry the tool's settings plus the aimed ball (`{ ball, club, pct, traj, axis, ideal, target, clubAuto, axisAuto, autoAim }`, Hit's ball already has the amateur miss), `refreshAim()` redraws the line when the game's target changes and `aimAt(x, z)` faces a target the player picked, `suggest({ club, axis })` sets the tool's recommendation, `mapSpot(x, z)` + `drawSpot()` + the `spot` event let a game's map set the next simulated shot's spot, `multiplier: false` + `badge(p)` turn off the ×4 streak and relabel its badge (Golf Bowling: bowling scoring is its own multiplier, the badge counts strikes in a row), and `award/stat(..., to)` credits another player.
- Each game has its own scene in `src/minigames/scenes/`, built on `src/world/stage.js` (renderer, sky, sun, fog, noise helpers, `terrainMesh`). A scene returns `{ renderer, scene, camera, sunDir, groundAt, surfaceAt, aimShadows, animate }`. (The old `range-world.js` is gone; a range-like game would build on `practice-ground.js` or its own scene.)
- `src/world/shot-view.js` gives every range-based game the ball, shadow, growing tracer, flight playback and stand-over-ball camera (`stance: { back, up, ballAt }` raises the view for games like Island Hopper where targets sit below you; `fov` narrows the lens so far targets read bigger, as in Golf HORSE).
- `src/minigames/aim.js` `solveShot()` finds ball data that reaches a target for simulated Hit / Ideal shot. Measure carry as true distance to the landing point, not downrange `r.carry`, or wide targets go badly wrong.
- Shape It's Launch Bay has no ground beyond the flight deck (`groundAt` is null over space), so the game flies shots with a `voidY` and gives the shot view `safeGround`. Its map is a 3D monitor parented to the camera (`createFlightPlanMonitor`), laid out in CSS pixels each frame and tapped by raycasting to the screen's UV; `kit.aimLine({ blockDrag })` keeps presses on it from dragging the aim line.
- Golf Bowling's toy room patches `THREE.ShaderChunk.lights_fragment_begin` for its own page so direct sun only lands where a window lets it in. It's per page (each game is its own page), but don't copy the trick into a shared module.
- Draw crowds with instanced meshes, one draw per body part, as Zombie Siege does in `src/minigames/zombie-horde.js`, not a group of meshes per character.
- Keep game rules pure in `<game>-logic.js` and test them in `tests/` (see `tests/shape-it.test.mjs`).
- Simulated swings should miss like a decent amateur (start direction σ≈3°, spin axis σ≈6.5°), so Beginner is generous but not automatic.
- Real-time `setTimeout` gaps between shots mean headless tests need `WAIT` steps between swings, not just `__advance`.
